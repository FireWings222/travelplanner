## 배경

이번 UI 개선 뒤에도 디자인 조사와 결정이 계속 생길 예정이다. 매번 형식이 다르면 나중에 무엇을 왜 정했는지 찾기 어렵다.

## 선택지

| 선택지 | 장점 | 단점 | 프론트엔드만으로 가능 |
|---|---|---|---|
| A. 결정 기록 문서 하나에 계속 추가 | 파일이 하나 | 길어지면 찾기 어려움, 결정 변경 이력이 섞임 | 해당 없음 |
| B. 결정 하나에 파일 하나(ADR 방식)와 목록 README | 결정별 상태 관리, 변경 시 이전 결정 보존 | 파일 수가 늘어남 | 해당 없음 |

## 결정

`doc/design/` 아래에 조사(`research/`)와 결정(`decisions/`)을 나눠 기록하고, `README.md`에 목록을 둔다. 결정은 ADR(Architecture Decision Record) 방식으로 하나에 파일 하나를 쓰고 번호를 붙인다. 템플릿은 각 폴더의 `_template.md`를 쓴다.

## 근거

결정을 바꿀 때 이전 파일을 "대체됨"으로 남기면 왜 바뀌었는지 이력이 남는다. 학생은 README 표 하나로 현재 상태를 볼 수 있다.

## 영향

- 바뀌는 파일: `doc/design/` 추가, `CLAUDE.md`의 문서화 항목
- 파일 이름은 영문 소문자와 하이픈으로 쓴다.
