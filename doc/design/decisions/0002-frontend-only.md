## 배경

Java 코드(서비스, 계산 로직, API)는 학생이 직접 설계하고 구현한 부분이다. UI 개선 때문에 서버 코드가 바뀌면 학생이 자기 코드를 설명하기 어려워지고 `main`과의 충돌 범위도 커진다.

## 선택지

| 선택지 | 장점 | 단점 | 프론트엔드만으로 가능 |
|---|---|---|---|
| A. 서버 응답까지 함께 수정 | 화면에 필요한 값을 서버에서 바로 받음 | 학생 코드 변경, 테스트 수정 필요, 충돌 범위 큼 | 불가 |
| B. 템플릿, CSS, JS만 수정 | 학생 코드 유지, 변경 범위가 화면에 한정 | 서버가 주지 않는 값은 화면에서 계산하거나 포기 | 가능 |

## 결정

UI 개선은 `src/main/resources/templates`와 `src/main/resources/static`(CSS, JS, 이미지)만 고친다. Java 코드, DB 마이그레이션, 설정 파일, REST API 요청과 응답 형식은 바꾸지 않는다.

## 근거

현행 진단 9건은 모두 화면 배치, 표시 방식, 화면에서의 계산으로 해결할 수 있다. 화면에 필요한 응답 필드(관광지 좌표, 구간 소요 시간, 1인 금액)도 이미 응답에 있음을 `dto/Travel.java`, `pricing/Pricing.java`에서 확인했다.

## 영향

- 바뀌는 파일: `templates/*.html`, `static/css/site.css`, `static/js/*.js`
- 하지 않기로 한 것: Java 코드 수정, 새 API 추가
- 외부 라이브러리를 쓰려면 `build.gradle`에 webjar를 추가해야 하므로 따로 결정한다.
