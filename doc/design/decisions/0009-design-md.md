# 0009. 디자인 규칙을 DESIGN.md로 정리

| 항목 | 내용 |
|---|---|
| 상태 | 결정 |
| 결정일 | 2026-11-23 |
| 결정한 사람 | 지도 교사 |
| 관련 문서 | [DESIGN.md](../../../DESIGN.md), [0005](0005-avoid-generated-look.md), [0006](0006-design-references.md), [0007](0007-draft-selection.md), [0008](0008-kakao-map.md) |

## 배경

지도 교사가 정한 시안을 학생에게 넘기면, 이후 메뉴나 버튼을 추가하는 작업은 학생이 한다. 학생이 같은 디자인 콘셉트로 이어서 작업하려면 색, 글꼴, 간격, 컴포넌트 사용 규칙이 한곳에 정리돼 있어야 한다. 학생이 AI 코딩 도구를 쓰더라도 같은 규칙을 따라야 한다.

## 선택지

| 선택지 | 장점 | 단점 | 프론트엔드만으로 가능 |
|---|---|---|---|
| A. 결정 기록(`doc/design/decisions`)만 남김 | 추가 문서 없음 | 규칙이 여러 결정 문서에 흩어져 있어 화면을 만들 때 찾기 어려움 | 해당 없음 |
| B. 저장소 루트에 DESIGN.md 작성 | 규칙이 한 파일에 모임, AI 코딩 도구가 읽는 공개 명세 형식(Google DESIGN.md) | 코드가 바뀌면 함께 고쳐야 함 | 해당 없음 |

## 결정

저장소 루트에 `DESIGN.md`를 둔다. 형식은 Google이 공개한 DESIGN.md 명세(`version: alpha`)를 따른다. 맨 위 YAML에 토큰(색, 글꼴, 모서리, 간격, 움직임, 컴포넌트)을 두고, 본문은 명세의 섹션 순서(Overview부터 Do's and Don'ts까지)에 한국어로 쓴다. 명세에 없는 "새 화면이나 버튼을 만들 때 점검할 것" 섹션을 맨 끝에 덧붙인다.

순서는 DESIGN.md를 먼저 쓰고, 경로 비교와 여행 일정 화면을 DESIGN.md대로 구현하면서 문서와 코드가 다른 곳을 고친다.

## 근거

- DESIGN.md는 Google Stitch가 내놓고 명세를 공개한 형식이며, 저장소 루트에 두면 AI 코딩 도구가 디자인 규칙으로 읽는다(공식 저장소 `google-labs-code/design.md`의 README와 `docs/spec.md` 확인).
- 값은 결정된 시안(시안 A, 원본 초록)의 CSS와 카카오맵 확인용 페이지 코드에서 옮겼다. 시안에 없는 주 버튼은 학생 원본 `site.css`의 `.primary` 값을 따랐다.
- 화면 문구 말투는 시안 문구(반말)가 아니라 학생이 쓴 기존 앱 말투("~하세요", "~합니다")를 따르도록 정했다.

## 영향

- 바뀌는 파일: `DESIGN.md` 추가, `CLAUDE.md`에 DESIGN.md를 따르라는 규칙 추가
- 이후 디자인 결정이 바뀌면 결정 기록과 함께 DESIGN.md도 고친다.

## 후속 확인

- [ ] 공식 lint 도구(`designmd lint DESIGN.md`)로 검사. 이 PC에 npm 패키지를 설치하지 않기로 해서 아직 돌리지 않았다. 토큰 참조 오류 0건, 섹션 순서 일치는 직접 확인했다.
- [ ] 경로 비교, 여행 일정 화면을 구현한 뒤 DESIGN.md 값과 실제 `site.css`가 같은지 확인
- [ ] 학생이 DESIGN.md만 보고 새 버튼이나 메뉴를 만들 수 있는지 학생 의견 받기
