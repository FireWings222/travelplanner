# 0001. UI 개선은 feature 브랜치에서 작업

| 항목 | 내용 |
|---|---|
| 상태 | 결정 |
| 결정일 | 2026-11-23 |
| 결정한 사람 | 지도 교사 |
| 관련 문서 | [0002 수정 범위](0002-frontend-only.md) |

## 배경

TravelPlanner는 학생의 포트폴리오 저장소이고 `main` 브랜치는 학생이 계속 작업한다. 지도 교사의 UI 개선 작업이 학생 작업과 충돌하지 않아야 한다.

## 선택지

| 선택지 | 장점 | 단점 | 프론트엔드만으로 가능 |
|---|---|---|---|
| A. `main`에 직접 커밋 | 브랜치 관리 불필요 | 학생 커밋과 충돌, 학생 작업 이력과 섞임 | 해당 없음 |
| B. `feature/*` 브랜치에서 작업 | 학생 작업과 분리, 병합 시점을 학생과 정할 수 있음 | 병합 전 `main` 변경을 따라가야 함 | 해당 없음 |

## 결정

UI 개선 작업은 `feature/*` 브랜치에서 한다. 첫 브랜치는 `feature/ui-redesign`이다. push와 병합은 지도 교사가 직접 한다.

## 근거

학생이 `main`을 계속 고치는 상황에서 같은 브랜치를 쓰면 충돌이 생긴다. 브랜치를 나누면 학생이 변경 내용을 검토한 뒤 받아들일 수 있다.

## 영향

- 바뀌는 파일: 없음(작업 방식 결정)
- 하지 않기로 한 것: `main`에 직접 커밋

## 후속 확인

- [ ] 병합 전에 `main`의 최신 변경을 반영하고 충돌 여부 확인
