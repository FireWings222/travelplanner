## 배경

DESIGN.md의 색, 글자, 간격 값은 학생 원본 `site.css`의 `:root` 값과 다르다. 예를 들어 원본 바탕색 `--bg`는 초록 기가 도는 회색(#f5f8f3)이고 글자색 `--ink`는 초록 기가 도는 검정(#152a22)이다. 같은 이름의 변수 값을 바꾸면 아직 새 디자인을 적용하지 않은 홈, 일일투어, 비용 비교 화면도 색이 일부만 바뀐다.

## 선택지

| 선택지 | 장점 | 단점 | 프론트엔드만으로 가능 |
|---|---|---|---|
| A. `site.css`의 `:root` 값을 한 번에 DESIGN.md 값으로 바꿈 | 변수 정의가 한 곳, 작업이 끝나면 정리할 것이 없음 | 옮기지 않은 화면은 색만 바뀌고 배치는 그대로라 어색함 | 가능 |
| B. 새 디자인을 적용한 화면의 `<body>`에 `redesign` 클래스를 붙이고, 그 안에서만 DESIGN.md 변수를 씀 | 옮기지 않은 화면은 지금 모습 그대로, 화면 하나씩 옮기고 확인 가능 | 모든 화면을 옮길 때까지 옛 변수와 새 변수가 함께 있음 | 가능 |

## 결정

B를 적용한다. 새 디자인을 적용한 화면만 `<body class="redesign">`을 붙이고, `site.css`의 `.redesign` 규칙 안에서 DESIGN.md 변수를 정의해 쓴다.

## 근거

- 화면을 하나씩 옮기면서 학생이 각 화면의 변화를 확인하고 설명할 수 있다.
- 옮기지 않은 화면이 반쯤 바뀐 모습으로 남지 않는다.

## 영향

- 바뀌는 파일: `site.css`(맨 아래 "새 디자인" 구역), 새 디자인을 적용한 화면의 템플릿과 JS
- 옮기는 방법은 DESIGN.md의 "새 디자인으로 옮기는 방법" 절에 적었다.
- 하지 않기로 한 것: 다크 테마는 머리글까지 새 디자인으로 바꾼 뒤(다음 할 일 3번) 적용한다. 지금은 머리글과 바닥글이 옛 디자인이라 한 화면 안에서 색이 섞이기 때문이다.

## 후속 확인

- [ ] 모든 화면을 옮긴 뒤 `.redesign` 변수를 `:root`로 올리고 옛 변수(`--bg`, `--muted`, `--line`, `--green`, `--mint` 등)와 옛 규칙을 지움
- [ ] 머리글을 새 디자인으로 바꿀 때 다크 테마 적용
