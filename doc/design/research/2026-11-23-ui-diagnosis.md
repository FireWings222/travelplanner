## 목적

UI 개선 우선순위를 정하기 위해 현재 화면에서 사용자가 막히거나 헷갈리는 곳을 찾는다.

## 범위와 방법

- 대상: 홈, 경로 비교, 여행 일정, 일일투어, 비용 비교 화면
- 코드 기준: `feature/ui-redesign` 브랜치(`main`의 `7824e97`과 같은 코드)
- 방법: `bootRun`으로 실행한 앱을 헤드리스 Chrome으로 열어 제주 샘플 흐름(홈에서 제주 샘플 불러오기, 여행 검색, 여행 일정, 일일투어, 제주 동부 일일 버스투어 비용 비교)을 실행하고 화면을 캡처했다. 화면 폭은 1280px, 1440px, 390px이다.
- 데이터: API 키 없는 샘플 모드, 서울에서 제주, 2027-03-10부터 3일, 성인 2명, 예산 450,000원
- 코드 확인: 화면에서 본 동작은 `static/js`, `dto/Travel.java`를 읽어 원인을 확인했다(코드는 고치지 않음).

## 확인한 사실

| 번호 | 화면 | 문제 | 영향 |
|---|---|---|---|
| 1 | 전체 | 메뉴는 나란히 있지만 실제로는 순서대로 써야 하는 구조 | 높음 |
| 2 | 전체 | 여행 전체 비용과 예산 비교가 어디에도 없음 | 높음 |
| 3 | 경로 비교 | 추천 경로와 비교표를 눌러서 적용할 수 없음 | 높음 |
| 4 | 경로 비교, 여행 일정, 비용 비교 | 구간 카드 안에서 같은 정보가 두 번씩 나옴 | 중간 |
| 5 | 여행 일정 | 하루씩만 보이고 지도 없이 목록만 있음 | 중간 |
| 6 | 일일투어 | 상품 목록보다 등록 폼이 더 크게 차지함 | 중간 |
| 7 | 비용 비교 | 결론 문장이 비용만 말하고 시간 차이는 빠짐 | 중간 |
| 8 | 모바일 | 비교표의 금액 열이 화면 밖으로 잘림 | 중간 |
| 9 | 홈, 공통 | 큰 제목 영역과 눌리지 않는 예시 카드 | 낮음 |

### 1. 메뉴는 나란히 있지만 실제로는 순서대로 써야 하는 구조

- 상단 메뉴는 경로 비교, 여행 일정, 일일투어, 비용 비교를 같은 수준으로 보여 준다. 실제로는 홈 검색을 먼저 해야 경로 비교와 여행 일정에 내용이 생기고, 투어를 골라야 비용 비교에 내용이 생긴다.
- 여행 조건 없이 메뉴에서 비용 비교를 누르면 "비교할 투어를 선택해 주세요" 안내만 나온다.
- 현재 단계와 다음 단계를 알려 주는 표시가 없다. 화면마다 상단 버튼 구성이 다르다.

### 2. 여행 전체 비용과 예산 비교가 어디에도 없음

- 예산은 상단 요약 줄에 "예산 450,000원"으로만 표시되고 다른 금액과 비교하지 않는다(`common.js`의 `showTrip`에서만 사용).
- 왕복 교통 295,600원은 경로 비교 화면에, 현지 일정 17,960원은 여행 일정 화면에 따로 있어 전체 비용을 사용자가 더해야 한다.
- 홈의 "여행 유형"은 서버로 보내지만 결과 계산에 쓰이지 않는다(`CatalogService`에서 그대로 돌려줌).

### 3. 추천 경로와 비교표를 눌러서 적용할 수 없음

- 교통수단 조합 12가지 표 아래 맨 끝에 추천 카드 4개(가장 짧은 이동, 가장 적은 환승, 가장 저렴한 이동, 비용과 시간 균형형)가 있다.
- 표의 행과 추천 카드는 읽기 전용이다. 추천 경로로 바꾸려면 구간 드롭다운 3개를 직접 바꿔야 한다.
- "(부분 합계)"가 붙은 행과 아닌 행이 같은 열에 섞여 있다.

### 4. 구간 카드 안에서 같은 정보가 두 번씩 나옴

- 공통 함수 `legCards`가 그리는 구간 카드에 구간 이름과 금액이 제목 줄과 비용 줄에 두 번 나온다.
- "테스트용 가상 가격" 배지, 확인 시각, "요금 직접 입력", "카카오맵에서 길찾기"가 모든 구간에 반복된다. 비용 비교 화면의 교통수단 조정 영역은 약 1,380px로 데스크톱 화면 높이(900px)의 1.5배다.

### 5. 하루씩만 보이고 지도 없이 목록만 있음

- 3일 일정을 "일자" 드롭다운으로 하루씩 바꿔 봐야 한다.
- 방문 순서는 위, 아래 화살표 버튼으로만 바꾼다. 관광지 위치 지도는 없다(구간별 "지도에서 보기"는 카카오맵 키가 있을 때만 표시).
- "일정 저장"은 보조 버튼이고 저장한 여행 목록은 화면 맨 아래에 있다.

### 6. 상품 목록보다 등록 폼이 더 크게 차지함

- 제주 투어 상품 1개 아래에 "투어 상품 직접 등록" 폼(입력칸 18개, 체크박스 8개)이 항상 펼쳐져 있다.
- 이미지가 없는 상품은 카드 왼쪽 3분의 1이 빈 그라데이션이다.
- "비교 목록에 추가"와 "비용 비교" 버튼의 차이가 화면에서 설명되지 않는다.

### 7. 결론 문장이 비용만 말하고 시간 차이는 빠짐

- 결론은 "자유여행이 101,760원 저렴해요"다. 이동 시간은 일일투어 2시간 0분, 자유여행 4시간 48분으로 2시간 48분 차이가 나지만 아래 카드 안에서만 확인할 수 있다.
- 투어 쪽 부대 비용 3줄(숙소에서 집합 장소, 종료 장소에서 숙소, 기타 필수비)이 모두 0원으로 나와 무료인지 입력하지 않은 것인지 구분되지 않는다.
- 비교 조건(날짜, 인원) 폼이 결과 아래에 있다.

### 8. 비교표의 금액 열이 화면 밖으로 잘림

- 390px 폭에서 경로 비교표 6열 가운데 "이동 방식"과 "편도 시간"만 보이고 금액 열 4개는 가로로 밀어야 보인다. 밀 수 있다는 표시는 없다.
- 표와 추천 카드를 합치면 약 1,150px로 휴대폰 화면 한 장(844px)보다 길다.

### 9. 큰 제목 영역과 눌리지 않는 예시 카드

- 홈 오른쪽 "2박 3일 여행 예시" 카드는 눌러도 반응이 없다. 같은 기능(제주 샘플 불러오기)은 검색 폼 오른쪽 위 작은 버튼에 있다.
- 작업 화면도 큰 제목(최대 52px)과 설명 문장을 써서 결과가 화면 위에서 약 390px 아래부터 시작한다.
- 제목 글자 간격(`letter-spacing: -.085em`)이 좁아 홈 제목 글자가 붙어 보인다.

## 결론

- 9건 모두 템플릿, CSS, JS만으로 고칠 수 있다. 2번의 예산 비교는 서버가 이미 주는 금액을 화면에서 더하면 된다.
- 영향이 큰 1, 2, 3번은 앱의 목적(여행 비용을 한 번에 비교하기)과 바로 연결된다.

## 미확인 사항

- ODsay, 카카오 API 키가 있을 때의 화면(실제 노선, 카카오맵 지도)
- 저장한 여행을 다시 여는 흐름, 투어 직접 등록 뒤 목록 표시, 오류 메시지 표시
- 키보드만 쓸 때와 화면 낭독기로 읽을 때의 사용성
